# ACH — Analysis of Competing Hypotheses

**Source:** Richards Heuer, CIA Intelligence Directorate. Jordan supplied the manual 2026-10-01 and
asked that it become the standing frame.

**Why it matters here:** standard analysis builds one case forward and then filters evidence to fit
it. That is exactly what this session did — "Jordan has too many lanes" was asserted early and every
later observation was read as support. ACH forbids that.

---

## The 8 steps

1. **Brainstorm hypotheses.** Mutually exclusive, exhaustive. **Include a contrarian and a deception
   scenario.**
2. **Compile evidence.** Data points, *missing* information, indicators, and structural assumptions.
3. **Structure the matrix.** Evidence down, hypotheses across.
4. **Refine and delete.** Group linked indicators; **delete anything with zero diagnostic value.**
5. **Falsification testing.** Conclude by **minimising inconsistency, never by maximising proof.**
6. **Sensitivity analysis.** If one key piece of evidence is wrong, does the matrix flip?
7. **Report probabilities.** Relative odds for all hypotheses, **and why the rejected ones failed.**
8. **Milestone monitoring.** Name future indicators that will confirm or break the winner.

## The scoring scale

| | Meaning | Weight |
| --- | --- | --- |
| **VC** | Very consistent — integrates completely | **Zero diagnostic value if it also fits other hypotheses** |
| **C** | Consistent — expected but not exclusive | Baseline only, low impact |
| **I** | Inconsistent — contradicts a baseline requirement | **High diagnostic value. Increments rejection** |
| **II** | Totally inconsistent — logically impossible | **Critical. Eliminates the hypothesis** |

**The rule that does all the work: evidence that fits every hypothesis is worthless.** Only
disconfirming evidence moves the analysis.

## The deception countermeasure

If a hypothesis comes out flawlessly clean — all VC, zero inconsistency — **score a parallel
hypothesis that the evidence itself is misinformation.** In this estate the equivalent is: *the
record is wrong.* That is not hypothetical. Twice on 1 October the project list was found to be
missing fifteen projects, so **"my own records are the artifact" is a live hypothesis, not a
courtesy.**

---

## Binding practice from 2026-10-01

- **Any claim about why a project is stuck gets competing hypotheses before a recommendation.**
  Minimum three, one of them contrarian, one of them "the evidence is wrong."
- **Delete non-diagnostic evidence out loud.** If an observation fits every explanation, say so and
  drop it rather than listing it as support.
- **Never present a single forward-built case as a finding.** State the odds and why the rejected
  alternatives failed.
- **Every conclusion ends with milestone indicators** — what would have to happen to break it.
- **Go looking for frameworks.** Jordan's instruction, 2026-10-01: *"you go out and look for
  frameworks that can help move these forward."* Frameworks live in this folder. A finding you have
  is a finding you surface, in the session, not when asked.
